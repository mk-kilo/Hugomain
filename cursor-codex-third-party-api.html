OFOX 官方说法 · 查阅于 2026-11-26

Ofox Desktop 与 CC Switch

这一节只转述当天重新打开的 Ofox 页面。Codex CLI 和 Claude Code 在本站仍是未验证。scripts/ofox-smoke.py 和 tests/ofox_smoke.py 都不启动这两个客户端。Cursor 直接接入仍然不兼容，也不在 Desktop 的十个工具里。

Ofox Desktop

Ofox Desktop 写的是：登录后选择已经安装的工具，点 Connect。Ofox 为每个选中的工具管理专用密钥，并写入该工具自己的接入设置。页面标题区点名 Claude Code、Codex、ChatGPT、OpenClaw，并说这些工具共用一个账户和一张账单。

兼容表在页面上标成 README · 1.5.0，同日打开的 GitHub README 也写「Supported in 1.5.0」。十个工具的一键接入都是勾：Claude Code、Codex、ChatGPT（Codex 模式）、OpenCode、Gemini CLI、OpenClaw、Hermes、WorkBuddy、DeepSeek Harness（dsh）、Pi。ChatGPT 这一行只覆盖 Codex 模式，和 Codex 共用配置与本地会话；普通 ChatGPT 云端对话不在这次接入里。

下载要求：macOS 12+、Apple Silicon，官方包已签名并公证；Windows 10/11 x64，安装包当前未签名，出现 SmartScreen 提示时先核对来源。同一页的 SoftwareApplication 结构化数据把 softwareVersion 写成 v1.5.3，和兼容表上的 1.5.0 是两个字段。Desktop 的下载表没有 Linux。应用本身免费，许可证是 MIT。模型、搜索和媒体按各自价格计费。

Codex 的桌面应用指南写明：Ofox Desktop 和 Codex Desktop 是两个应用。一次只用一种配置工具，避免设置被互相覆盖。装上配置工具本身，并不等于 API 已经接通。

CC Switch

Codex 与 Claude Code 的模型提供商指南都建议用 CC Switch，并同时给出 Ofox Desktop 作为更快的设置方式。macOS 安装命令是：

brew install --cask cc-switch

同一页还写了 macOS 的 .dmg、Windows 的 .msi，以及 Linux 的 deb、rpm、AppImage。CC Switch 的系统要求是 macOS 12+、Windows 10+、Ubuntu 22.04+ / Debian 11+ / Fedora 34+。

Codex 在 CC Switch 里切到 Codex 标签。请求地址是 https://api.ofox.ai/v1，末尾不加斜杠，API 格式选 OpenAI Compatible，并写入全局 config.toml。Claude Code 在这里只作为客户端工具：请求地址是 https://api.ofox.ai/anthropic，末尾不加斜杠，格式保持 Anthropic Messages (Native)，认证字段保持 ANTHROPIC_AUTH_TOKEN，CC Switch 写入 ~/.claude/settings.json。通用 CC-Switch 页把另一处 API Base URL 写成 https://api.ofox.ai/v1；Claude Code 专页和集成说明写的是 https://api.ofox.ai/anthropic。按正在配置的客户端对照专页。

手工字段，供对照

Ofox 集成说明把 Codex 的文件写成 ~/.codex/config.toml。下面把该说明里的提供商字段，和正文里的 wire_api = "responses" 放在一起。Codex 指南同样写明 CLI 使用 OpenAI Responses API，而且不是每个模型都支持这个格式。示例里的具体模型 id 没有照抄。Codex CLI 仍是未验证。

model_provider = "ofoxai"

[model_providers.ofoxai]
name = "OfoxAI"
base_url = "https://api.ofox.ai/v1"
env_key = "OFOXAI_API_KEY"
wire_api = "responses"

env_key 是环境变量名。密钥留在本机环境里，不写进公开页面。

同一份集成说明里的 Claude Code 环境变量，和 CC Switch 专页的请求地址、认证字段一致：

export ANTHROPIC_BASE_URL=https://api.ofox.ai/anthropic
export ANTHROPIC_AUTH_TOKEN=<OFOXAI_API_KEY>

Claude Code 是 Anthropic 的编码客户端。这里不指定 Claude 模型。模型 id 以目录里该协议实际列出的为准。

Ofox 自己的核对界限。 Claude Code 文档写明：仅凭一条回复，不能确定是哪一家供应商处理了这次请求；如果需要工具调用，要在一次性项目里单独测试，文本响应不是工具兼容性测试。Codex Desktop 指南写的是：回复加上对得上的用量记录，只核对这条请求路径，并不能单独证明模型身份，也不能证明工具调用、图片输入或结构化输出。

常见问题

为什么充了 API 额度，Cursor Tab 还是不动？

Tab、Background Agent 和 Auto 按 Ofox 的说明不走自定义供应商。额度买的是 API 调用，不是这些编辑器功能。

能不能把一份 Ofox 的 Codex 配置直接贴进 config.toml？

下一节转述 Ofox 写明的字段，包括 ~/.codex/config.toml 的 base_url https://api.ofox.ai/v1，以及 wire_api 的值 responses。本站没有运行 Codex CLI，所以仍是未验证。字段对不上就会报错。Ofox 还写明：仅凭一条回复，不能确定是哪一家供应商处理了这次请求；文本响应也不是工具兼容性测试。

Claude Code 是不是已经测通了？

没有，仍是未验证。tests/ofox_smoke.py 不启动 Claude Code。Ofox 把 Claude Code 写成客户端工具，基址是 https://api.ofox.ai/anthropic，认证变量是 ANTHROPIC_AUTH_TOKEN。只支持 OpenAI 的 /v1 不能填进 ANTHROPIC_BASE_URL。Ofox 的 Claude Code 文档写明：仅凭一条回复，不能确定是哪一家供应商处理了这次请求；文本响应也不是工具兼容性测试。
