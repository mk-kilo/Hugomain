MODEL IDS

调用前，先从目录里抄模型 id

OpenAI 兼容接口的模型列表是 GET {根地址}/models。Ofox 的根地址是 https://api.ofox.ai/v1，所以列表地址是 https://api.ofox.ai/v1/models。你要放进 model 字段的，是响应里每个对象的 id，不是宣传页上的商品名。

读一次列表

本仓库的 scripts/fetch_ofox_public_prices.py 不带密钥请求这个地址，并且只在 HTTP 200 和可用的 JSON 列表时才写入观察文件。服务商以后若改为必须带密钥，就加上与聊天接口相同的 Authorization: Bearer。现在不要假设未登录读取永远可用。

curl · 不把密钥写进命令
curl https://api.ofox.ai/v1/models

在返回的 JSON 里找 data 数组。每一项的 id 是调用字符串。若该项还带有端点或价格字段，那是该次响应自己的内容；本页不转抄，以免变成一份过期价目。

id 怎么用

  1. 从 id 原样复制，包括斜杠。本站示例写成 openai/gpt-5.4，是因为 2026-11-12 的公开目录包含这个 id，不包含 openai/gpt-5.6。那是目录事实，不是推荐排名。
  2. 把同一个字符串放进 Chat Completions 的 model。写法见 Python / Node / curl。
  3. 列表里没有的 id，不要靠记忆补上。补出来的名字是 404 / model not found 的常见原因。
  4. 同一条 id 不一定每个端点都能用。仓库记录的 Ofox 文档说明是：openai/gpt-5.4-pro 和 Codex 系列只走 Responses API。只在 Chat Completions 里看到别的 id，不能推断这两个也能用。

仓库里的 ofox-public-prices.json 是一次带时间的观察。有可用文本单价的模型才列入，没有单价的放在 missing，不会被补一个数字。它不能代替你刚才请求到的列表。

常见问题

模型 id 写在响应的哪里？

OpenAI 兼容的列表响应里，每个模型对象的 id 字段就是调用时要原样填写的字符串。不要用展示名称代替 id。

仓库里的 ofox-public-prices.json 能不能当当前目录？

不能。那是某一次未登录读取的观察，文件里写了时间。当前 id 以 GET https://api.ofox.ai/v1/models 的当场响应为准。没有文本单价的模型在那份文件里不会被补上一个数字。
