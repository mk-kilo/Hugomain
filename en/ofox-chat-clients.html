Keep Ofox chats in a client that stores them

This page is for chat clients that keep the conversation on the device or on an instance you run. Ofox’s OpenAI-compatible root is https://api.ofox.ai/v1. The chat path is https://api.ofox.ai/v1/chat/completions. Create the key in the Ofox console at Settings → API Keys → Create New Key. The key is shown once. Ofox’s error doc says to keep the sk- prefix. Ofox’s own articles write the example key as starting with sk-of-.

Cherry Studio

The desktop custom-provider doc says: click Settings (the gear) in the left bar, select Model Provider, then click + Add Provider at the bottom of the list. That opens Add Custom Provider. Cherry Studio custom provider

  1. Set Provider Name to a name you will recognize, such as Ofox. Put the Ofox key in API Key. The model-service settings page also describes Add API key inside the API Key field, then Save and close. Model service settings
  2. Under Endpoint settings, fill the OpenAI API root. Leave the Anthropic, Gemini, and image URL fields for other protocols. This page uses the OpenAI chat endpoint. A preview of the final request path appears under the field.
  3. Click Add. On the provider page, turn on the switch in the upper right. The doc says a disabled provider’s models stay out of the model list.
  4. Click Sync models to the right of the Models heading and add the models you will use. The + beside it takes a Model ID, Model Name, and Group Name. The Model ID is the full catalog id, such as openai/gpt-5.4.
  5. Click Model Check to the right of API Key. The doc says the check uses the last chat model added to the list.

Ofox’s Cherry Studio page sets the API Host for both OpenAI Chat and OpenAI Response to https://api.ofox.ai/v1, and says not to add a trailing slash. Accessed 2026-11-26. Ofox Cherry Studio doc

Cherry Studio’s own desktop doc splits the address the other way: when the provider’s full address looks like https://xxx.xxx.com/v1/chat/completions, enter only https://xxx.xxx.com. The app appends /v1/chat/completions. A host of https://api.ofox.ai plus the path /v1/chat/completions is the same request as Ofox’s https://api.ofox.ai/v1. An address that ends in / gets only chat/completions appended, so https://api.ofox.ai/v1/ lands on the same path. An address that ends in # is used as entered, which is how https://api.ofox.ai/v1/chat/completions# is written. The preview under the field should show exactly https://api.ofox.ai/v1/chat/completions.

The phone app uses different labels. Open Settings → Model service, tap add, choose Custom provider, select the OpenAI API format, and set Base URL to a root that includes /v1, which is https://api.ofox.ai/v1. Leave /chat/completions out of that field. Fetch the list or type the model id, confirm the provider is enabled, and run the connection check on a text model. The mobile doc also says to add one key per entry, rather than pasting several keys into one field. Cherry Studio mobile docs

Where the chats are, and how to back them up

Data stays in the user directory. The documented defaults are macOS /Users/yourname/Library/Application Support/CherryStudio, Windows C:\Users\yourname\AppData\Roaming\CherryStudio, and Linux /home/yourname/.config/CherryStudio. Settings → Data → Data Directory shows the live path on the App Data row, and Open Directory opens it. Storage location

Backups are under Settings → Data. A full backup includes conversations and topics, assistants, knowledge bases, attachments, preferences, and provider configuration. API keys are included. Lite backup skips image, knowledge-base, and other data files and keeps chat history and settings. Click Backup at any time, or turn on automatic backup at the interval the screen offers. Local backup is another folder on disk. WebDAV or S3-compatible storage is the documented way to move a backup from one computer to another. The backup contains keys. Keep the file off shared drives you do not trust. Data settings

Chatbox

The provider guide is eight steps. The English doc and the Chinese doc in the docs repo name the same controls: the settings button in the sidebar, Model Provider, Add, OpenAI API compatible, API Key, API Host, and Check. English guide · Chinese guide in the repo

  1. Open Chatbox and click the settings button in the sidebar.
  2. Open Model Provider. If Ofox is not in the list, click Add at the bottom.
  3. Enter an API provider name. Choose OpenAI API compatible. The Gemini option is a different API type.
  4. Enter the API Key and API Host. The doc says the API path can usually be left alone. Its default is /v1/chat/completions.
  5. Add at least one model. Capability checkboxes are optional. An unconfigured model is treated as a plain text model. Use the full catalog id, such as openai/gpt-5.4.
  6. Save, then click Check. The doc says a successful check reports that the connection succeeded. Go back to the home page, start a conversation, and send a message.

Ofox’s Chatbox page sets the API Host for both OpenAI API Compatible and OpenAI Responses API Compatible to https://api.ofox.ai/v1. Accessed 2026-11-26. Ofox Chatbox doc

Chatbox’s own provider doc defaults the API path to /v1/chat/completions. If that field stays at the default, the host is https://api.ofox.ai and the default path supplies the rest. That pairing and Ofox’s API Host https://api.ofox.ai/v1 are two ways to split one request: one puts /v1 in the host, the other puts it in the path. Do not put /v1 in both. If the path field on your build shows /chat/completions, use Ofox’s https://api.ofox.ai/v1 as the host. The finished request is https://api.ofox.ai/v1/chat/completions.

Where the chats are, and how to back them up

Chatbox’s user guide says chat history stays on the device and is not uploaded to Chatbox’s servers. Desktop paths are Windows %APPDATA%\chatbox\, macOS ~/Library/Application Support/chatbox/, and Linux ~/.config/chatbox/. iOS uses the app sandbox. Android uses app private storage. The same guide says that a third-party API receives the messages you send. A local transcript still leaves the device as the API request.

Export is Settings → Data Management → Export Data. JSON is the format the guide describes for backup and recovery. Markdown is for reading and archiving. On Android the file is saved under Documents/chatbox_ai_exports. To restore, install Chatbox on the new device, open the same screen, choose Import Data, and pick the JSON file. The guide says there is no automatic multi-device sync, and Chatbox’s servers cannot restore a lost local history. Export the JSON before you change devices. Data storage

When the connection fails, read the status code

The codes below follow Ofox’s error doc as it read on 2026-11-26. Ofox error handling A longer walkthrough is on OpenAI-compatible API errors.

  1. 401 is an invalid or missing API key, code invalid_api_key. Check for a copied space or newline, check that the key is still enabled, and check that the pasted value is the Ofox key. A key issued for api.openai.com does not call api.ofox.ai. Ofox says this status is not fixed by retrying.
  2. When a request fails, see the Ofox error-code guide.
  3. A base URL missing /v1, or a URL with /v1 twice. Some clients append /v1/chat/completions. Others default the path to /v1/chat/completions. The finished request is https://api.ofox.ai/v1/chat/completions. A wrong path commonly comes back as 404.
  4. Model not found. Ofox describes 404 and not_found_error as a missing model or resource. Compare the id in the client with the id field from GET https://api.ofox.ai/v1/models, character for character. A key that is not allowed to call that model is a different code: 403, model_not_allowed. Change the models that key is allowed to use.

How to keep the key

  1. Ofox shows the key once, at creation. If it is lost, create a new key. Pasting the old one into a chat, a ticket, or a screenshot does not recover it.
  2. Examples on this page use YOUR_API_KEY. Keep a real key out of Git, off public pages, out of forms on this site, and out of a backup you share.
  3. Cherry Studio’s full backup includes provider configuration and API keys. Chatbox stores API keys on the device. Anyone who can open that device or that backup can use the key.
  4. Ofox’s key doc recommends a separate key per project and an IP Whitelist on the key. It also recommends rotating keys, and the interval they name is 90 days. Key setup
