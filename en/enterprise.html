Team limits, logs, routing, and related APIs

The notes below repeat Ofox docs and the changelog opened again on that date. Volume bonus or credit percentages follow the checkout page. This site has not toggled these console controls, and it has not called the video or Decisions APIs.

Limits and access · 2026-11-09

The changelog entry “Team Management · Nov 9, 2026” and Limits & Access describe the same console page: Settings → Limits & access. Only a team Owner or Admin can change the rules. Edits to the IP allowlist, allowed models, and budgets are kept in Change history at the top right. Log-retention settings are not in that history.

  • Budgets sit at three levels: team, member, and API key. The period can be Daily, Monthly, or Total. The action is Notify and block, or Notify only. A request is blocked as soon as any level runs out. Within the same period, a key budget cannot exceed that member’s budget, and a member budget cannot exceed the team budget. Ofox says topping up does not restore calls once a budget is used up. Raise the cap, or wait for the daily or monthly period to reset.
  • The team IP allowlist allows only listed IPv4 addresses or CIDR ranges, up to 100 entries. A key list narrows the team list further. An address on a key’s list takes effect only when it is also on the team list. Other addresses are rejected. The documented code is 403 ip_not_allowed.
  • Allowed models has three modes: All models, Only these models, and Block these models. A key can narrow the list again. A model has to pass both the team rule and the key rule. The documented code for a block is 403 model_not_allowed.
  • Check effective rules, in the key menu, shows whether a chosen model would be blocked and how much budget is left. The check does not use credits.

Request logs · 2026-11-09

Request Logs says retention is off by default: Ofox does not save request content. When debugging is needed, an Owner or Admin turns on Log retention from the top right of Activity, for all keys or for selected keys. New requests then save input, output, tool calls, and the error reason. Images are saved only if Also save images is selected. API keys, tokens, passwords, and similar credentials are replaced with [REDACTED] before saving. Storage stops at the latest 3 days, 10,000 requests, or 1 GB. When any limit is reached, the oldest logs are deleted. One request can skip saving with the header X-OfoxAI-Log-Content: off. The doc’s FAQ says log retention has no extra charge. Members cannot view log content.

Request rate

The limits page marks request rate as view only and links to Rate Limits. That page sets the default RPM at 100, aggregated across the whole team, so every key in the team shares one quota. A higher quota is requested from hi@ofox.ai. Excess requests get 429 Too Many Requests. Changelog v1.1.0 (2026-04-28) already stated the same team aggregate and the default of 100 RPM.

Provider routing · 2026-08-26

The changelog entry “Provider Routing · Aug 26, 2026” is where Ofox records pinning a request with provider.type. Leave it out and the gateway spreads requests by weight, so the provider for one call is not predictable. Text protocols use extra_body.provider.type, or the header X-OfoxAI-Provider-Type. Gemini’s native protocol ignores that body field and accepts only the header. Video uses a top-level provider.type. An unknown name returns invalid_provider_type. A provider that does not serve the model returns provider_type_unavailable. Content policy can differ between providers of the same model, so name the provider when that matters.

The current provider routing guide lists openai, anthropic, gemini, azure_foundry (foundry), aws_bedrock (bedrock), google_vertex (vertex), aliyun, alicloud, volcengine, byteplus, deepseek, moonshot, zhipu, zai, minimax, grok, jina, and tencent. Not every provider serves every model. Field locations are in API · Provider routing.

Analytics · 2026-06-16

The changelog entry “Analytics · Jun 16, 2026” merges the old usage and cost pages into one Analytics page: call volume, spend, and tokens in one view, with switches for model, member, API key, and app, plus a custom date range. The entry point named there is the console Analytics page. A request for /docs/develop/observability/analytics.md returned 404, so the changelog is the source for this item.

Model Verify

Model Verify (模型验真) is a free tool with a Chinese-language page. It sends active probes to the relay base URL that was entered and compares the responses with calibrated Claude, GPT, and Gemini behavior. The page says a high score means this response is closer to the baseline. It is not proof of identity, and it does not prove which model sits behind the API. Changelog v1.0.47 (2026-04-07) introduced the tool. The limit above follows the verify page opened on 2026-11-26. The tool itself is free. The probes make several model requests to the endpoint entered, and that provider may charge under its own rules.

Video API and Decisions API

The Video API is asynchronous. POST /v1/videos creates a task and returns 202 with the task id. GET /v1/videos/{id} is polled until the status is completed, failed, cancelled, or expired. DELETE /v1/videos/{id} cancels a task. The auth header is Authorization: Bearer. Resolution, duration, and price vary by model. This page does not list unit prices.

The Decisions API is documented. Three URLs serve the same models and differ in request format: POST https://api.ofox.ai/v1/decisions, POST https://api.ofox.ai/openai/v1/decisions, and POST https://api.ofox.ai/typesafe/v1/systemone. The result is a typed decision (yes/no, a single choice, or a score), not free text. The doc’s model table lists typesafe/jev-latest (text or JSON; it does not read images) and openai/gpt-6-luna, which the page says can read images.
