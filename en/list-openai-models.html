MODEL IDS

Copy the model id from the catalog before you call

The OpenAI-compatible model list is GET {root}/models. Ofox’s root is https://api.ofox.ai/v1, so the list URL is https://api.ofox.ai/v1/models. The value for the model field is each object’s id, not the product name on a marketing page.

Read the list once

scripts/fetch_ofox_public_prices.py requests this URL without a key, and it writes an observation only after HTTP 200 and a usable JSON list. If the provider later requires a key, add the same Authorization: Bearer header the chat call uses. Do not assume an unauthenticated read stays available.

curl · no key in the command
curl https://api.ofox.ai/v1/models

In the JSON, open the data array. Each item’s id is the call string. If that item also has endpoint or price fields, they belong to that response. This page does not copy them into a price list that would go stale.

How to use the id

  1. Copy id exactly, including the slash. Samples on this site use openai/gpt-5.4 because the public catalog on 2026-11-12 included that id and did not include openai/gpt-5.6. That is a catalog fact, not a ranking.
  2. Put that same string in the Chat Completions model field. The shapes are on Python / Node / curl.
  3. Do not invent an id that is absent from the list. A remembered name is a common cause of 404 / model not found.
  4. One id is not automatically valid on every endpoint. This repo’s note of the Ofox docs says openai/gpt-5.4-pro and the Codex series are Responses-only. Seeing other ids on Chat Completions does not mean those two are available there.

ofox-public-prices.json is one dated observation. A model is listed only when that response had a usable text rate. Missing rates are not filled in. The file does not replace the list you just fetched.

Questions

Where is the model id in the response?

In an OpenAI-compatible list, the id field on each model object is the string you copy into the request. Do not substitute a display name.

Can ofox-public-prices.json stand in for the live catalog?

No. That file is one unauthenticated observation and it records the time. Current ids come from the live GET https://api.ofox.ai/v1/models response. Models without a usable text rate are not given a number in that file.
