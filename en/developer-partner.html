Two ways to integrate

API key / base URL preset

Add Ofox as an optional provider only if the tool already accepts a custom endpoint and you have tested that combination. The user creates the key at Ofox. The tool must not upload a key or ship a shared one.

OAuth 2.1 (Beta)

Ofox marks Partner OAuth as Beta and says it is rolling out gradually. Accessed 2026-11-26: Partner OAuth doc. Send the app and callback URLs to Ofox first. Implement authorization and token handling only after Ofox registers the OAuth app. A referral link is not a substitute for OAuth.

Channel attribution

Ofox’s note: a new binding is created only when someone registers through the channel for the first time. An existing Ofox account does not change channel because they authorize an app or switch tools.

Checks before you publish

Protocol test

Exercise the protocol your tool actually needs — Chat Completions, Responses, or Messages — including streaming, tool calls, and error handling.

Security and scopes

OAuth has to use the callback Ofox registered. Check state, PKCE, and the scope that was actually granted. Store tokens in a safe place. A token without llm.invoke cannot call a model.

Commercial check

Confirm the live model price, which channel the user belongs to, the first-top-up rule, support, and whether commission can be counted. Current channel revenue does not predict the result after a tool integration.

First top-up bonus

On the public Partner rules, a user who signs up through a qualifying referral and completes a first top-up can receive an extra $3. Eligibility stays on Ofox’s page. It is not cash at signup, and JXZNE does not pay the bonus. Ofox’s Partner page says Ofox covers that $3.
