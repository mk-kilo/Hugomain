BASE URL

Set a base URL in tools whose docs allow a custom endpoint

This page covers five tools. Each tool’s own documentation describes an OpenAI-compatible API root other than https://api.openai.com/v1. Ofox documents the matching root as https://api.ofox.ai/v1. Filling in that root is not a client test this site has run. Every section below is unverified.

Cursor, Claude Code, and Codex are not on this list. Ofox marks direct Cursor use as unsuitable. Codex and Claude Code do not necessarily speak Chat Completions, and this site has not verified those clients.

Open WebUI

Open WebUI’s OpenAI-compatible guide says to open Settings → Connections, add an OpenAI API connection, set the URL to the provider’s /v1 root, and set the API key. If model discovery is unavailable, add model ids to the allowlist. Open WebUI docs

Connection fields · not a verified Ofox session
URL: https://api.ofox.ai/v1
API Key: YOUR_API_KEY
Model ID if discovery fails: openai/gpt-5.4

That doc also shows OPENAI_API_BASE_URL and OPENAI_API_KEY. Menu names move between versions. Follow the doc for the version you installed.

Continue

Continue’s OpenAI provider doc says that for an OpenAI-compatible server you set provider: openai and point apiBase at that server’s /v1 root. Continue docs

config.yaml · field names from Continue’s doc
name: Example
version: 0.0.1
schema: v1
models:
  - name: Example model
    provider: openai
    model: openai/gpt-5.4
    apiBase: https://api.ofox.ai/v1
    apiKey: YOUR_API_KEY
    useResponsesApi: false

The same page says Continue uses OpenAI’s /responses endpoint by default for o-series and gpt-5 models. Their doc shows useResponsesApi: false when you need Chat Completions. Whether a model id is offered on /chat/completions, /responses, or both is a provider catalog question. This site has not called Ofox from Continue.

LibreChat

LibreChat’s custom-endpoint doc says that omitting provider uses the OpenAI-compatible client, that baseURL is the API root, and that the app appends /chat/completions. Set directEndpoint: true only when baseURL is already the full completions URL. LibreChat docs

librechat.yaml · each user supplies a key
endpoints:
  custom:
    - name: "Ofox"
      apiKey: "user_provided"
      baseURL: "https://api.ofox.ai/v1"
      models:
        default: ["openai/gpt-5.4"]
        fetch: true

user_provided is their documented value: each person types a key in the UI instead of committing one. This site has not run LibreChat.

Cline

Cline’s OpenAI Compatible doc says to select API Provider “OpenAI Compatible”, then enter Base URL, API Key, and Model ID. The Base URL is the root from the provider you chose, not https://api.openai.com/v1. Cline docs

Cline setting fields
API Provider: OpenAI Compatible
Base URL: https://api.ofox.ai/v1
API Key: YOUR_API_KEY
Model ID: openai/gpt-5.4

Their troubleshooting describes “Model Not Found” as a model id or Base URL that does not match that provider. This site has not installed Cline to check Ofox.

LiteLLM

LiteLLM’s OpenAI-compatible doc names two changes: prefix the model with openai/ so LiteLLM uses the OpenAI client, and set api_base to the compatible endpoint. The same doc says a Not Found error means you should check that api_base includes /v1. LiteLLM docs

Python · LiteLLM’s openai/ prefix
import litellm

response = litellm.completion(
    model="openai/openai/gpt-5.4",
    api_base="https://api.ofox.ai/v1",
    api_key="YOUR_API_KEY",
    messages=[{"role": "user", "content": "Hello"}],
)

The prefix looks repeated because two names are stacked. The leading openai/ is LiteLLM’s route. The rest, openai/gpt-5.4, is the model id in the Ofox catalog. This site has not run this snippet.

Questions

Are these configs verified with Ofox?

No. Each section only records that the tool’s own docs allow a custom OpenAI-compatible base URL. This site has not run Open WebUI, Continue, LibreChat, Cline, or LiteLLM against Ofox. The status is unverified.

Why are Cursor, Claude Code, and Codex absent?

Ofox marks direct Cursor use as unsuitable. This site has not verified the Codex or Claude Code clients, and those tools do not necessarily speak Chat Completions. The limits are on the setup guides and when Cursor or Codex will not take a third-party API. Do not infer that they take the same base URL.
