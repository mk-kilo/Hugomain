脚本会调用什么

对照 Ofox 文档：OpenAI 兼容基址是 https://api.ofox.ai/v1，Chat Completions 是 POST https://api.ofox.ai/v1/chat/completions，认证头是 Authorization: Bearer 加上原始 Key。Chat Completions 文档 · 快速开始

2026-11-12 拉取的公开目录 GET /v1/models 共 131 个 id。其中有 openai/gpt-5.4，没有 openai/gpt-5.6。同日目录里的 5.6 系列是 openai/gpt-5.6-sol、openai/gpt-5.6-luna、openai/gpt-5.6-terra。Ofox 的 GPT 文档写明 openai/gpt-5.4-pro 和 Codex 系列只支持 Responses API，所以这次冒烟不用它们。

Python · 与脚本相同的请求格式
curl https://api.ofox.ai/v1/chat/completions \
  -H "Authorization: Bearer $OFOX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-5.4","messages":[{"role":"user","content":"Reply with OK only."}],"max_tokens":16}'

怎样跑出一条真实记录

  1. 在 Ofox 控制台复制原始 API Key。不要加 Bearer ，不要带引号或换行。
  2. 在仓库根目录执行下面的命令。Key 只留在当前 shell，不要写进文件或命令历史以外的提交。
Shell
read -rs OFOX_API_KEY
export OFOX_API_KEY
python3 scripts/ofox-smoke.py

有 Key 时，脚本向 Chat Completions 发一次请求，并把 model、latencyMs、status、httpStatus、timestamp 写入 ofox-smoke-status.json。没有 Key 时打印 BLOCKED_NO_OFOX_API_KEY，退出码 0，不改状态文件。

仓库 Actions「Ofox chat completions smoke」可手动运行，并在每周一 06:00 UTC 运行。它使用名为 OFOX_API_KEY 的 Actions secret。Secret 为空时不请求 Ofox，也不提交状态文件。

这条记录不能说明的事

  • Cursor 直接接入：Ofox 兼容性说明写明 Tab、Agent、Auto 不会走自定义供应商。Cursor 兼容性说明。本站不把它写成可用。
  • Codex CLI 与 Claude Code：Ofox 有配置指南（Codex、Claude Code）。本脚本不启动这两个客户端，所以它们保持未验证。
