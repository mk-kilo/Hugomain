GUIDE 01

Codex：模型提供商配置

Codex CLI / IDE 扩展读取个人配置文件 ~/.codex/config.toml。官方支持配置模型和提供商，但需要所选服务兼容 Codex 所需的请求协议，并支持目标模型。官方配置文档 ↗

  1. 安装并更新官方 Codex，确认本机可以正常运行。
  2. 打开 ~/.codex/config.toml，查阅官方文档中的 model_provider、model_providers 和 wire_api 配置方式。
  3. 向 API 服务商确认：是否支持 Codex 使用的 Responses 协议、模型名及认证方式。仅仅支持 OpenAI Chat Completions 并不代表一定兼容。
  4. 先以小规模测试调用验证工具操作、长输出和稳定性，不要立即大额充值。
兼容状态：待实际验证。目前不提供未经测试的 Ofox Codex 配置文件，避免用户复制后出现报错。

GUIDE 02

Claude Code：LLM Gateway 接入

Claude Code 有独立的 Anthropic API 调用格式。官方支持通过 LLM Gateway 路由请求，但上游网关必须暴露兼容接口。官方网关文档 ↗

  1. 先按官方教程安装并完成基础运行测试。
  2. 询问服务商是否明确提供兼容 Anthropic Messages 的网关、工具调用、流式输出及模型 ID。
  3. 如果网关确认兼容，可以参考官方示例设置如下环境变量（请使用服务商提供的真实值）：
Shell · 示例变量（不是可直接工作的 Ofox 配置）
export ANTHROPIC_BASE_URL="https://YOUR-COMPATIBLE-GATEWAY"
export ANTHROPIC_AUTH_TOKEN="YOUR_API_KEY"

注意：不要把 API Key 发布到 GitHub 或公开网页中。不同网关的认证头和路径可能不同，应以服务商与官方文档为准。

兼容状态：待实际验证。不要直接把仅支持 OpenAI 格式的 /v1 端点填入 ANTHROPIC_BASE_URL。

GUIDE 03

Cursor：不建议直接接入 Ofox

Cursor 支持在设置中配置部分模型提供商的个人 API Key，但该功能并不覆盖所有 Cursor 特性。官方 API Keys 文档 ↗

  1. 打开 Cursor Settings → Models（具体菜单随版本可能变化）。
  2. 确认目标提供商和模型位于官方支持范围，按页面说明添加 Key 并点击 Verify。
  3. 检查是否支持你要用的自定义 Base URL；若使用第三方聚合 API，应先确认 Cursor 当前版本与该平台的兼容情况。
  4. 通过实际聊天、代码编辑等任务测试。Tab Completion 等特定功能可能仍使用 Cursor 自有服务。
兼容状态：Ofox 官方标记为不兼容。Cursor Tab、Background Agent 和 Auto 模式不适合直接使用 Ofox。建议在 Cursor 内置终端运行 codex 或 claude，前提是先分别完成它们的 Ofox 配置。参考 Ofox 官方兼容性公告 ↗。

TROUBLESHOOTING

遇到报错，先检查这些

出现 401 Unauthorized？

检查密钥是否属于该 API 平台、有没有复制空格、是否已启用额度，以及认证头是否符合目标工具所需协议。不要在公开帖子中粘贴密钥。

出现 404 或 Model not found？

检查端点路径、请求协议和模型 ID。Codex 的 Responses 与部分 OpenAI 兼容接口不是同一种功能；Claude Code 需要兼容 Anthropic 格式的网关。

出现 429 / 限速？

查看余额、并发量、令牌速率和上游容量限制，降低请求频率后重试。

为什么充值后 Cursor Tab 或官方订阅不生效？

第三方模型 API 额度与 Codex、Claude Code、Cursor 的官方订阅分开计费；某些功能需要官方服务。
