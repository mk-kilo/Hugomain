把 Ofox 对话留在自己的客户端里

这一页写的是会在本机或自建实例里保存对话的聊天客户端。Ofox 的 OpenAI 兼容根地址是 https://api.ofox.ai/v1，对话请求的完整路径是 https://api.ofox.ai/v1/chat/completions。密钥在 Ofox 控制台的 Settings → API Keys 里点 Create New Key 创建，只显示一次。Ofox 的错误说明要求保留 sk- 前缀；Ofox 自己的文章把示例密钥写成 sk-of- 开头。

模型 id 用公开目录里的完整字符串。2026-11-26 请求 GET https://api.ofox.ai/v1/models 时，目录里有 openai/gpt-5.4、openai/gpt-5.4-mini 和 deepseek/deepseek-v4.1-flash。目录会变。添加之前用 同一条列表接口 再对一次。短名字、你记得的旧名字，都不算这个 id。

Cherry Studio

桌面版的自定义提供方文档写的是：左侧点 Settings（齿轮），在设置页左侧选 Model Provider，在提供方列表底部点 + Add Provider，打开 Add Custom Provider。Cherry Studio 自定义提供方

  1. Provider Name 填一个你认得的名字，例如 Ofox。API Key 填这把 Ofox 密钥。同一页的模型服务设置还写了另一种入口：在 API Key 栏点 Add API key，粘贴后点 Save and close。模型服务设置
  2. Endpoint settings 里填 OpenAI 的 API 根地址。Anthropic、Gemini 和图像地址留给别的协议；这一页只用 OpenAI 对话端点。字段下方会预览最终请求路径。
  3. 点 Add 保存。回到该提供方页面，打开右上角的启用开关。文档写明开关关掉时，模型不会出现在选择列表里。
  4. 在 Models 标题右侧点 Sync models，把要用的模型加进列表。也可以点旁边的 +，手工填 Model ID、Model Name 和 Group Name。Model ID 用目录里的完整 id，例如 openai/gpt-5.4。
  5. 点 API Key 右侧的 Model Check。文档写这次检查默认用模型列表里最后加入的对话模型。

桌面文档对 API Host 的规则是：服务商若给出 https://xxx.xxx.com/v1/chat/completions，只填根地址 https://xxx.xxx.com，程序会接上 /v1/chat/completions。按这条规则，Ofox 的桌面 API Host 填 https://api.ofox.ai。地址以 / 结尾时，程序只接 chat/completions，所以 https://api.ofox.ai/v1/ 也会落到同一条路径。地址以 # 结尾时，程序按你输入的地址原样请求，可写成 https://api.ofox.ai/v1/chat/completions#。看字段下的预览，最终路径应正好是 https://api.ofox.ai/v1/chat/completions。

手机文档是另一套字段。路径是 Settings → Model service，点 add，选 Custom provider，API 格式选 OpenAI，Base URL 按文档示例写成带 /v1 的根地址，也就是 https://api.ofox.ai/v1，不要再写 /chat/completions。然后抓取或手工加入模型 id，确认提供方已启用，再对一个文本模型做连接检查。手机文档还写明一个密钥一条记录，不要把多把密钥粘进同一个输入框。Cherry Studio 手机文档

聊天记录和备份

数据在本机用户目录。文档给出的默认位置是：macOS /Users/用户名/Library/Application Support/CherryStudio，Windows C:\Users\用户名\AppData\Roaming\CherryStudio，Linux /home/用户名/.config/CherryStudio。Settings → Data → Data Directory 里的 App Data 一行显示实际路径，Open Directory 会打开它。存储位置

备份在 Settings → Data。文档写的完整备份包含对话和话题、助手、知识库、附件、偏好，以及提供方配置；API 密钥也在备份里。Lite backup 打开后会跳过图片和知识库等数据文件，保留聊天记录和设置。可以随时点 Backup，也可以打开按间隔运行的自动备份。本地备份是另选一个文件夹；跨电脑可以用 WebDAV 或 S3 兼容存储，在一台机器备份、在另一台恢复。备份文件含密钥，不要发给别人，也不要放到不受信任的共享盘。数据设置

Chatbox

Chatbox 文档仓库里的模型配置是这八步。英文文档站的同页用的是对应英文名：settings、Model Provider、Add、OpenAI API compatible、API Key、API Host、Check。中文说明 · 英文说明

  1. 打开 Chatbox，点侧边栏的设置按钮。
  2. 点「模型提供方」。列表里没有 Ofox 时，点底部的「添加」。
  3. 填写 API 提供方名称。类型选「OpenAI API兼容」。Gemini 用的是另一项，这一页不选它。
  4. 填写 API 密钥和 API 主机。API 路径文档写的是一般不用填，默认为 /v1/chat/completions。

  6. 保存后点「检查」。文档写成功时会提示连接成功。回到首页新建对话再发一条消息。

聊天记录和备份

Chatbox 的用户指南写明：聊天记录在本地设备，不会上传到 Chatbox 的服务器。桌面路径是 Windows %APPDATA%\chatbox\，macOS ~/Library/Application Support/chatbox/，Linux ~/.config/chatbox/。iOS 在应用沙盒内，Android 在应用私有存储。指南同时写明，使用第三方 API 时，发出去的消息会到达你填写的那家服务；本机留档不等于请求不离开这台设备。

导出路径是设置 → 数据管理 →「导出数据」。JSON 是指南里用于备份和恢复的完整数据，Markdown 用于阅读和归档。Android 上文件会保存到 Documents/chatbox_ai_exports。恢复是在新设备进入同一页，选「导入数据」，再选先前的 JSON。指南写明目前没有自动的多设备同步，Chatbox 的服务器也不能把丢失的本地记录找回来。换机时先在旧设备导出 JSON。数据存储（中文） · Data storage

连接失败时先看状态码

状态码以下面 Ofox 的错误说明为准，查阅于 2026-11-26。Ofox 错误处理更长的对照在 OpenAI 兼容 API 常见错误。

  1. 401 是无效或缺失的 API Key，错误码 invalid_api_key。核对有没有多复制空格或换行，密钥有没有被禁用，以及粘贴的是不是这把 Ofox 密钥。发给 api.openai.com 的密钥不能调用 api.ofox.ai。Ofox 写明这个状态不要靠重试解决。
  2. 402 且错误码为 insufficient_credits 表示余额不足。在 Ofox 控制台充值后再发。同一个 402 若是 spending_limit_exceeded，表示团队、成员或这把密钥的支出上限已到；文档写明充值不能解开，需要提高上限，或等到每日、每月周期重置。
  3. 根地址少了 /v1，或写了两层 /v1。客户端有的自己补 /v1/chat/completions，有的把默认路径设成 /v1/chat/completions。最终请求应正好是 https://api.ofox.ai/v1/chat/completions。路径不对时，常见结果是 404。
  4. 模型找不到。Ofox 把 404、not_found_error 写成模型或资源不存在。把客户端里的 id 和 GET https://api.ofox.ai/v1/models 的 id 字段逐字对比。密钥不允许该模型时是另一个码：403、model_not_allowed，到控制台改这把密钥允许的模型。

密钥怎么放才安全

  1. Ofox 写明密钥只在创建时显示一次。丢了就新建一把，而不是把旧密钥贴进聊天、工单或截图去找人恢复。
  2. 示例里只出现 YOUR_API_KEY。不要把真实密钥写进 Git、网页、本站表单，或和别人共享的备份。
  3. Cherry Studio 的完整备份包含提供方配置和 API 密钥。Chatbox 把 API 密钥存在本机。谁能打开那台设备或那份备份，谁就能使用这把密钥。
  4. Ofox 的密钥说明建议用不同密钥区分项目，并在密钥菜单里用 IP Whitelist 限制来源。文档还建议定期轮换，他们写的间隔是 90 天。密钥说明

常见问题

这些客户端是不是已经用 Ofox 测通？

不是。每一节只复述该客户端在 2026-11-26 仍能打开的官方文档或仓库说明。本站没有安装 Cherry Studio、Chatbox、LobeChat 或 Open WebUI 去调用 Ofox。

Cherry Studio 的 API Host 填哪一段？

Ofox 的根地址是 https://api.ofox.ai/v1。桌面文档写明程序会接上 /v1/chat/completions，所以桌面 API Host 填 https://api.ofox.ai。手机文档的 Base URL 示例带 /v1，填 https://api.ofox.ai/v1。以路径预览为准，最终只保留一层 /v1。

401 和 402 分别表示什么？

401 是无效或缺失的 API Key。402 且错误码为 insufficient_credits 表示余额不足。同一个 402 若是 spending_limit_exceeded，表示支出上限已到，充值不能解开。

聊天记录存在哪里？

Cherry Studio 在本机的 CherryStudio 目录，备份在 Settings → Data。Chatbox 在本机的 chatbox 目录，导出在设置 → 数据管理。LobeChat 的部署文档写记录在本地浏览器。Open WebUI 在服务器的 webui.db，账户导出在 Settings → Data Controls → Export Chats。

Cursor、Claude Code 和 Codex 能用同一套地址吗？

本页不写这三款编程工具。Ofox 把直接接入 Cursor 标为不合适。Codex 和 Claude Code 的客户端本站没有验证，而且它们要的协议不一定是 Chat Completions。边界在 配置教程 和 Cursor / Codex 接不上时。
