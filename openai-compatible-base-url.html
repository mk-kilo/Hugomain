BASE URL

在官方支持自定义端点的工具里填写 Base URL

这一页只写五款工具。它们自己的文档说明可以填写一个 OpenAI 兼容的接口根地址，而不是只允许 https://api.openai.com/v1。Ofox 文档中的对应根地址是 https://api.ofox.ai/v1。把地址填进去，不等于本站已经用该客户端打通过 Ofox。下面每一节都是待实测。

Cursor、Claude Code、Codex 不在这张清单里。Ofox 把直接接入 Cursor 标为不合适。Codex 和 Claude Code 要的协议也不等于 Chat Completions，本站没有验证那两个客户端。

Open WebUI

Open WebUI 的 OpenAI 兼容说明写的是：在 Settings → Connections 里管理 OpenAI API 连接，添加一条连接，URL 填服务商的 /v1 根地址，再填 API Key。模型列表接口不可用时，把模型 id 写进允许列表。Open WebUI 文档

连接字段 · 不是已验证的 Ofox 会话
URL: https://api.ofox.ai/v1
API Key: YOUR_API_KEY
Model ID（自动发现失败时）: openai/gpt-5.4

同一份文档也给出环境变量 OPENAI_API_BASE_URL 和 OPENAI_API_KEY。菜单名称会随版本变化，以你安装的那一版文档为准。

Continue

Continue 的 OpenAI 提供商文档写明：对 OpenAI 兼容服务，把 provider 设为 openai，并用 apiBase 指向该服务的 /v1 根地址。Continue 文档

config.yaml · 摘自 Continue 的字段名
name: Example
version: 0.0.1
schema: v1
models:
  - name: Example model
    provider: openai
    model: openai/gpt-5.4
    apiBase: https://api.ofox.ai/v1
    apiKey: YOUR_API_KEY
    useResponsesApi: false

同一页写着：默认情况下，Continue 对 o 系列和 gpt-5 模型使用 OpenAI 的 /responses。若你要走 Chat Completions，他们的文档给出 useResponsesApi: false。模型 id 是否同时提供 /chat/completions 和 /responses，以服务商当时的模型卡片为准。本站没有用 Continue 调用过 Ofox。

LibreChat

LibreChat 的自定义端点文档写明：不设置 provider 时走 OpenAI 兼容客户端；baseURL 是 API 根地址；程序会在后面接上 /chat/completions。只有 baseURL 已经是完整的 completions 地址时，才把 directEndpoint 设为 true。LibreChat 文档

librechat.yaml · 密钥让每位用户自己填
endpoints:
  custom:
    - name: "Ofox"
      apiKey: "user_provided"
      baseURL: "https://api.ofox.ai/v1"
      models:
        default: ["openai/gpt-5.4"]
        fetch: true

user_provided 是他们的文档值：每位用户在界面里输入自己的密钥，而不是把密钥写进配置文件。本站没有跑过 LibreChat。

Cline

Cline 的 OpenAI Compatible 说明写的是：在设置里把 API Provider 选成 OpenAI Compatible，然后填写 Base URL、API Key 和 Model ID。Base URL 不是官方的 https://api.openai.com/v1，而是你选的那家服务商给出的根地址。Cline 文档

Cline 设置字段
API Provider: OpenAI Compatible
Base URL: https://api.ofox.ai/v1
API Key: YOUR_API_KEY
Model ID: openai/gpt-5.4

他们的故障排查把 “Model Not Found” 解释为模型 id 或 Base URL 与该服务商不匹配。本站没有安装 Cline 去验证 Ofox。

LiteLLM

LiteLLM 的 OpenAI 兼容文档写了两处改动：模型名前面加 openai/，表示用 OpenAI 客户端去调一个兼容端点；api_base 指向该端点。文档还写着，如果出现 Not Found，确认 api_base 带有 /v1。LiteLLM 文档

Python · LiteLLM 的 openai/ 前缀
import litellm

response = litellm.completion(
    model="openai/openai/gpt-5.4",
    api_base="https://api.ofox.ai/v1",
    api_key="YOUR_API_KEY",
    messages=[{"role": "user", "content": "Hello"}],
)

前缀看起来重复，是因为两层名字叠在一起。开头的 openai/ 是 LiteLLM 的路由前缀。后面的 openai/gpt-5.4 是 Ofox 目录里的模型 id。本站没有运行这段代码。
