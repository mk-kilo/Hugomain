OPENAI-COMPATIBLE API

用 Python、Node 或 curl 调用一个 OpenAI 兼容接口

官方 OpenAI SDK 把“哪一家服务”和“哪一个模型”分开。你保留原来的 chat.completions.create，只改两处：接口根地址，以及服务商目录里的模型 id。Ofox 文档中的 OpenAI 兼容根地址是 https://api.ofox.ai/v1。下面三段代码是这个形状。它们不是本站已经记录通过的调用。冒烟状态仍是待实测。

调用前先对齐这三件事

  1. 根地址用 https://api.ofox.ai/v1。Python 参数名是 base_url，Node 参数名是 baseURL。不要在 SDK 的根地址后面再加 /chat/completions，SDK 会自己接上。
  2. 密钥放在环境变量或本机密钥管理里，请求头由 SDK 写成 Authorization: Bearer。不要把密钥写进仓库、网页或下面的示例。
  3. 模型 id 用服务商目录里的完整字符串。本站示例用 openai/gpt-5.4，因为 2026-11-12 的公开目录包含这个 id，不包含 openai/gpt-5.6。目录会变，发送前用 模型列表接口再对一次。

Python 的 base_url 见 openai-python 说明。Node 的 baseURL 见 openai-node。Ofox 的 Chat Completions 说明见 Ofox 文档。

Python

安装官方包 openai 后，构造客户端时传入根地址。下面的 YOUR_API_KEY 是占位符。

Python · 官方 SDK
from openai import OpenAI

client = OpenAI(
    base_url="https://api.ofox.ai/v1",
    api_key="YOUR_API_KEY",
)

response = client.chat.completions.create(
    model="openai/gpt-5.4",
    messages=[{"role": "user", "content": "Hello"}],
)

print(response.choices[0].message.content)

密钥也可以不写在代码里。官方客户端会读取环境变量 OPENAI_API_KEY。若只改地址，把密钥留在环境变量，OpenAI(base_url="https://api.ofox.ai/v1") 即可。

Node

官方包是 openai。注意大小写：这里是 baseURL，不是 Python 的 base_url。

Node · 官方 SDK
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://api.ofox.ai/v1",
  apiKey: process.env.OPENAI_API_KEY,
});

const response = await client.chat.completions.create({
  model: "openai/gpt-5.4",
  messages: [{ role: "user", content: "Hello" }],
});

console.log(response.choices[0].message.content);

curl

curl 没有 SDK，所以地址要写到方法本身，只写一次 /chat/completions。密钥从环境变量读，不要写进 shell 历史可以分享的脚本里。

curl
curl https://api.ofox.ai/v1/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-5.4","messages":[{"role":"user","content":"Hello"}]}'

常见问题

base_url 要不要带上 /chat/completions？

Python 和 Node 的官方 SDK 不要带。写成 https://api.ofox.ai/v1，SDK 会自己请求 /chat/completions。curl 要写完整地址 https://api.ofox.ai/v1/chat/completions，只写一次。

示例里的 openai/gpt-5.4 是不是已经测通？

不是。它是请求格式里的模型 id。2026-11-12 的公开目录包含这个 id，不包含 openai/gpt-5.6。本站冒烟记录仍是待实测。

401、404、429 或超时先看哪里？

先核对密钥、路径和模型 id，再看频率和客户端超时。逐步说明在 OpenAI 兼容 API 常见错误。
